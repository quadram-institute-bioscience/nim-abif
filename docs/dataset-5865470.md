# Dataset 5865470

> This dataset comes from [Zenodo record 5865470](https://zenodo.org/records/5865470) and the
> related paper [SangeR: The high-throughput Sanger sequencing analysis pipeline](https://academic.oup.com/bioinformaticsadvances/article/2/1/vbac009/6517778?login=true).

## Description

This dataset contains Sanger trace files in AB1 format. The traces come from glioma cell lines and patient samples. Each trace covers one hotspot locus used in the SangeR paper. The dataset is useful for checking whether `abiscreen` can detect known hotspot calls and return wild-type calls for matching controls.

The main loci are:

- TERT promoter C250 and C228
- IDH1 R132 and G105
- IDH2 R172
- H3F3A K28 and G34

The downloaded record includes a `mutation` directory with positive examples and a `no_mutation` directory with wild-type control traces.

## Get the dataset

Use [download_zenodo_5865470.sh](../tests/download_zenodo_5865470.sh) to download and unpack the Zenodo record into `./datasets/5865470`.

```bash
bash tests/download_zenodo_5865470.sh datasets/5865470
```

The output directory must be missing or empty before you run the script. The script downloads the Zenodo archive, checks the nested ZIP files, expands them, and verifies the expected AB1 file counts.

After a successful download, the directory should contain:

```text
datasets/5865470/
+-- mutation/
+-- no_mutation/
+-- *.ab1
```

The `mutation` directory contains 12 AB1 files. The `no_mutation` directory contains 20 AB1 files. The top-level AB1 files are copies from the Zenodo archive and are not needed for the `abiscreen` example below.

The current `abiscreen` fixture panel is stored in [targets.tsv](../tests/fixtures/5865470/targets.tsv), with reference sequences in [refs.fa](../tests/fixtures/5865470/refs.fa). It covers TERT promoter C250 and C228, IDH1 R132 and G105, IDH2 R172, and H3F3A K28.

Two calls in the paper table need care when using the downloaded traces as automated tests:

- Patient 1 has `IDH1 R132H` in the paper table, but the downloaded trace gives a clean reference base at the panel position used by `abiscreen`.
- Patient 5 has `H3F3A G34R` in the paper table, but the current `abiscreen` fixture panel does not include an H3F3A G34 target.

## Using abiscreen

Build the command-line tools first:

```bash
nimble buildbin
```

Then run `abiscreen` on the positive and negative control traces:

```bash
bin/abiscreen \
  -i datasets/5865470/mutation \
  -i datasets/5865470/no_mutation \
  -p tests/fixtures/5865470/targets.tsv \
  -r tests/fixtures/5865470/refs.fa \
  -o screen-out \
  --report html,csv,vcf
```

This creates:

- `screen-out/run.html`, an interactive HTML report with chromatogram evidence
- `screen-out/calls.csv`, a table of per-target calls
- `screen-out/calls.vcf`, variant calls in VCF format
- `screen-out/failed.csv`, files that failed processing

An example HTML report is available at [abiscreen-5865470.html](abiscreen-5865470.html).

The dataset-specific regression test is [test_abiscreen.nim](../tests/test_abiscreen.nim). It runs `abiscreen` against the downloaded files when `datasets/5865470` is present, then compares the output with [5865470_calls.csv](../tests/golden/5865470_calls.csv).

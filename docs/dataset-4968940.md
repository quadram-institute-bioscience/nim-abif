# Dataset 4968940

> This dataset comes from [Zenodo record 4968940](https://zenodo.org/records/4968940) and the
> related paper [High-quality SNPs from genic regions highlight introgression patterns among European white oaks](https://doi.org/10.1101/388447).
> The raw traces were originally deposited at [Dryad record 10.5061/dryad.4mw6m906j](https://doi.org/10.5061/dryad.4mw6m906j).

## Description

This dataset contains raw Sanger trace files in AB1 format. The traces come from a European white oak resequencing study. They cover many gene regions from *Quercus petraea*, *Quercus robur*, and one *Quercus ilex* outgroup sample.

The dataset is useful for testing `nim-abif` at large scale. It can check AB1 parsing, FASTQ export, metadata extraction, chromatogram rendering, and batch quality control.

The raw traces are grouped by locus. Most loci contain forward and reverse reads for each tree and for a negative control.

## Get the dataset

Use [download_zenodo_4968940.sh](../tests/download_zenodo_4968940.sh) to download and unpack the Zenodo record into `./datasets/4968940`.

```bash
bash tests/download_zenodo_4968940.sh datasets/4968940
```

The script downloads `qpqr_ori_ab1_final.zip`, checks its MD5 digest, unpacks the raw trace archive, and tries to clone the related `Reference.Db.SNPs.Quercus` repository into the output directory.

After a successful download, the directory should contain:

```text
datasets/4968940/
+-- qpqr_ori_ab1_final/
|   +-- ab1.id
|   +-- CL100CT134/
|   |   +-- CL100CT134_01-11P-F.ab1
|   |   +-- CL100CT134_01-11P-R.ab1
|   |   +-- ...
|   +-- CL1099CT11339/
|   +-- ...
+-- Reference.Db.SNPs.Quercus/
```

The local copy inspected for this documentation has a raw trace directory of about 7.9 GB.

## Filename anatomy

Each trace filename stores the locus, sequencing batch, individual, and read direction.

Example:

```text
CL100CT134_01-Ar18-F.ab1
```

| Part | Meaning |
|---|---|
| `CL100CT134` | Gene region or amplicon locus |
| `01` | Sequencing batch |
| `Ar18` | Individual tree identifier |
| `F` | Forward read direction |
| `R` | Reverse read direction |

The dataset also contains a small number of `F2` and `R2` traces. These are useful for checking how a batch utility handles repeated reads.

## Ground truth

This dataset does not provide a small hotspot ground truth table like [dataset 5865470](dataset-5865470.html). It is better suited to broad validation of parsers and batch tools.

Useful checks include:

- every AB1 file can be parsed;
- sequence length and quality length agree;
- forward and reverse traces can be identified from filenames;
- `ab1.id` can be compared with files present on disk;
- metadata tags can be extracted across many instruments runs;
- representative traces can be converted to FASTQ;
- chromatograms can be rendered for selected reads.

For `abiscreen`, this dataset needs extra preparation. A user must choose loci, prepare matching reference sequences, and build a `targets.tsv` file from known variant positions before running a hotspot screen.

## Using nim-abif tools

Build the command-line tools first:

```bash
nimble buildbin
```

Convert one AB1 trace to FASTQ:

```bash
bin/abi2fq --no-trim \
  datasets/4968940/qpqr_ori_ab1_final/CL100CT134/CL100CT134_01-11P-F.ab1 \
  CL100CT134_01-11P-F.fq
```

Inspect metadata from one trace:

```bash
bin/abimetadata \
  datasets/4968940/qpqr_ori_ab1_final/CL100CT134/CL100CT134_01-11P-F.ab1
```

Render a chromatogram from one trace:

```bash
bin/abichromatogram \
  datasets/4968940/qpqr_ori_ab1_final/CL100CT134/CL100CT134_01-11P-F.ab1 \
  -o CL100CT134_01-11P-F.svg
```

`abiscreen` can be used after creating a locus-specific reference FASTA and target panel:

```bash
bin/abiscreen \
  -i selected-traces/ \
  -p targets.tsv \
  -r refs.fa \
  -o oak-screen \
  --report html,csv,vcf
```

The current `abiscreen` input scan reads direct `.ab1` files from each input directory. This dataset is nested by locus, so whole-dataset screening needs a wrapper, a flat selected-trace directory, or recursive input support.
